## FILES

#### __init__.py

Bare `from . import html_locate` / `json_extract` / `request_code` / `snippets` — makes those four
submodules reachable as package attributes without curating a specific public API; it re-exports no
individual names. Full design for this package — decisions made with the user, phasing, the snippet engine,
XHR capture — lives in `SCRAPER_DESIGN.md` (repo root); read it in full before touching anything here or in
`ui/web_viewer/`, `ui/editor_script/`, `ui/scraper_inspector/`, and add new scraper decisions there, not in
this file. The Molex/Yazaki/KET part scrapers that use the code generated by this subsystem live in the
**sibling repo** (`harness_designer_database/scrapers/`), not here — see repo-root ``harness_designer/database/MAP.md` DESIGN NOTES` ("The Molex
part scraper lives in the sibling repo", "Other manufacturer scrapers").

#### assistant.py

The scraper assistant's logic — `SYSTEM_PROMPT`; `AssistantContext` (what the open page offers;
`ScraperInspector` implements it); `list_items()`/`assemble()` (which context pieces can be sent and the
exact message built from them, with a per-piece byte budget and a total cap); `request_summary()` (secret
headers omitted, JSON digested for display); `extract_code_blocks()`/`proposed_script()`/`unified_diff()`
for parsing Claude's reply.

#### assistant_tools.py

`make_tools()` — the four tools Claude can call to check a selector or JSON path against the real page
(`find_text`, `test_css_selector`, `test_xpath`, `inspect_json`); each runs on a worker thread, not the GUI
thread.

#### browser_pick.py

The JS that finds the element under the pointer in the live page and builds a selector, `parse_pick()`
(validates the answer), and `pick_snippet()`.

#### capture_hook.py

The JavaScript injected into every page that records `fetch`/`XMLHttpRequest` calls and reports them through
a `QWebChannel` object named `bridge`; also exposes `window.__hdPageSource()` (re-download the page without
it showing up as a captured request).

#### capture_model.py

`CapturedRequest` (one finished call — `is_json`, `parsed_json()`, `to_spec()`) and `parse_record()`, which
validates what the page reports — **treated as untrusted input**, since it comes from JS running on an
arbitrary third-party page.

#### examples.py

`EXAMPLES` — the script editor's Examples menu, showing how to keep a socket/`Event` on a thread so a
*second* script can end a first script's stuck wait ("Release a stuck script") — the user-facing answer to
`runner.py`'s own Stop limitation below.

#### highlight.py

`highlight_spans()` — one-pass Pygments highlighting (HTML/XML/JSON) returned as plain data, not tied to
any widget.

#### html_locate.py

`LocatedDocument` (source offset → enclosing element, built from `html.parser` positions; an element is
re-found in generated code by tag name + document order in the tree) and the element actions (`css_text`,
`css_all`, `css_attribute`, `xpath_text`, `xpath_all`, `xpath_attribute`). Selectors skip machine-generated
class names and pin only the tree level that actually needs `:nth-of-type`.

#### json_extract.py

JSON-path clicks → extraction code (`generate_extraction_code`, with `every_item=` for "this field from
every element", plus `suggest_name`, `snippet_for`); `describe()` asks Claude (through `../plugins/plugins/claude_ai/`, formerly `../claude/` before that package's
relocation under `plugins/plugins/`) to
describe a JSON structure in words.

#### request_code.py

`RequestSpec` → `requests`-library code (`generate_request_code`, `generate_page_load`). **Cookie and
Authorization headers are never written into generated code** — a deliberate security choice, not an
oversight. Handles JSON, urlencoded, and multipart request bodies.

#### runner.py

`Runner`/`ScriptRun` — a generated/edited script runs in a **daemon thread of this same process** with its
own namespace and its own `print`. `ScriptRun.request_stop()` raises `SystemExit` in that thread via
`PyThreadState_SetAsyncExc`, which **cannot reach a thread blocked at the OS level** (`time.sleep`, a socket
read, `.join()`, a bare `except` swallowing it) — the Stop button then stays pending indefinitely, and a
catastrophic regex can freeze the whole app. This was the **user's explicit decision** (2026-10-17), taken
against the author's recommendation of running scripts in a child process instead; do not move it to a child
process without asking first. Mitigated with a warning popup and teaching examples (see `examples.py` and
`SCRAPER_DESIGN.md`'s "Running scripts" section). A running script's public attributes are readable by other
scripts via `threading.enumerate()`. This is a known, accepted limitation, not a bug to fix unprompted.

#### script_builder.py

`snippet_block()` (turns warnings into `# NOTE:` comments) and `import_text()`/`import_position()` (where
new imports go in generated code, never duplicated).

#### script_files.py

`read_script()`, `write_script()` (atomic write), `scratch_path()` (the autosaved working copy path).

#### snippets.py

`Snippet` + the source-text actions (`split_at_every`, `text_after`, `text_before`, `find_position`,
`between`, `regex_capture`, `regex_all`). A selection is `document[start:end]`; generated code must reproduce
it when run. Markers grow until their FIRST occurrence is the selected one, and the snippet warns when it
had to; `Names` hands out collision-free variable names.

#### soft_wrap.py

`SoftWrap` — the document with extra line breaks inserted for display (minified pages are often one giant
line) plus the map from display positions back to offsets in the original text, including across CRLF line
endings.

#### url_input.py

`normalize_url()` — turns address-bar text into a real URL.

#### Scraper tool: design lives in SCRAPER_DESIGN.md (repo root) (started 2026-10-16)
Built-in QtWebEngine browser + XHR/source inspector + script editor + Claude assistant, as docks in `MainFrame`. Decisions made with the user and the full design (snippet engine, XHR capture via a page-world JS hook relayed through `QWebChannel`, Claude assistant, run/stop plan, phasing) are in `SCRAPER_DESIGN.md` -- read it in full before touching anything under `scraping/`, `ui/web_viewer/`, `ui/editor_script/` or `ui/scraper_inspector/`, and add new scraper decisions THERE, not here. Standing decisions: generated/Claude-written scripts may use `requests` + `beautifulsoup4` + `lxml`; the Claude client uses the official `anthropic` SDK with the user's own keyring-stored key; a script runs in a THREAD of the app process with a Stop button that raises `SystemExit` in it (USER'S decision 2026-10-17, taken against my recommendation of a child process): that cannot reach a thread blocked in `time.sleep`/a socket read/`join()`/a bare `except`, and a catastrophic regex freezes the whole app; the user accepted both, with a warning popup and teaching examples (SCRAPER_DESIGN.md "Running scripts") -- do not move it to a child process without asking. There are no unit tests (see "Do not write unit tests"); importing `harness_designer` has Config/logger side effects, so a scratch experiment must load modules without running the package `__init__`.
