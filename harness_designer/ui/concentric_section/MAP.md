## FILES

#### __init__.py

Plain package marker (copyright line only). NEW 2026-10-25. This package is the concentric-twist cross-section widget; design in `CONCENTRIC_TWIST_DESIGN.md` (repo root), section 9.

#### info_panel.py

The right-hand information pane. `WireInfoPanel(QWidget)` shows what is known about the wire selected on the left: an enlarged drawing of it (`CablePreview`), then part number, colour (+ stripe), size, the wire's length calculated along its helix, the current through it, its approximate maximum temperature (red and "(over its rating)" / "(thermal runaway)" when the solver flags it), the run length, layer and lay direction, conductor, insulation, OD and conductor count. The key fields come first; the construction details scroll below them. `show_wire(detail, cable, straight_length_mm, helix_length_mm)` fills it, `clear()` empties it. Everything is a plain `section_model.WireDetail`; nothing here reads the database. Module-level `format_length` (mm / m / ft, the same text the circuit editor's wire card uses), `format_current` and `format_temperature` ("not available" when `None`). PITFALL (found 2026-10-25): the content is inside a `QScrollArea` ON PURPOSE -- a `QSplitter` does not pass height-for-width on to its panes, so wrapped value labels were clipped to one line. Values are `ui.widgets.wrap_label.WrapLabel` (text the app does not control, e.g. a part number).

#### packing.py

Circle packing for a multi-conductor cable's conductors: packed as tightly as possible inside as near a circle as possible. `pack_circles(radii)` (cached, hashable argument) returns each circle's centre relative to the middle of the enclosing circle and that circle's radius. Exact for 1-7 equal circles (a ring, or a ring around a centre circle) and any two circles; for more, or for mixed sizes, the best of a ring-around-a-pack construction (`_ring_pack`, equal circles only) and a few seeded numeric relaxations (sunflower seed, pull to the middle, push apart). Deterministic, so a cable always draws the same way. Measured 2026-10-25 for equal circles: 8, 9 and 13 are optimal; 8-19 are within 0-6.5% of the best known enclosing radius (best-known values quoted from memory, not re-fetched); no overlaps; 0.3-0.4 s cold for 8-19 conductors, then cached. `envelope_factor(count)` = enclosing diameter / circle diameter. +y is DOWN (screen), so "top" is -y.

#### section_host.py

`ConcentricSectionHost(QMdiArea)` (NEW 2026-10-25) -- hosts a `ConcentricSectionWidget` in a hidden `QMdiSubWindow` exactly as `ui/pegboard_table/mdi_host.py`'s `PegboardTableHost` hosts a wire table (never shown on a real screen; real Qt title bar, close button, drag-to-move and drag-to-resize), and imports that module's coordinate constants rather than copying them (`SUB_WINDOW_ANCHOR`, `PIXELS_PER_MM`, the rest point, the oversized area, `_CursorAndCloseFilter`), so a section and a table share one coordinate frame. It also owns the SYNTHETIC EVENT DISPATCH -- `dispatch_hover` / `dispatch_press` / `dispatch_double_click` / `dispatch_drag_move` / `dispatch_release` / `dispatch_wheel`, `clear_hover`, `has_press` / `cancel_press`, `hover_cursor` -- which `objects_pegboard/section.py` calls after turning a canvas pixel into a point in the host's frame; kept here because it needs no GL and can be run against the real widget. The wheel goes only to the scroll area under the pointer (the information pane) and returns `False` over anything else. `grab_rgba()` is `PegboardTableHost.grab_rgba` verbatim. `resize_sub_window()`: in a scratch run the title bar's close button stopped answering clicks after a programmatic resize until the sub-window was deactivated and re-activated, so the resize does that; unconfirmed in the real app. Checked 2026-10-25 against the real widget in scratch scripts: a click selects a cable, a drag moves it as one unit, the sash drags closed and open, the hover cursor over the sash is `SplitHCursor`, the wheel scrolls the pane, a title-bar drag moves the sub-window, the close button emits `close_requested`.

#### section_model.py

Plain-data description of a bundle cross-section; touches neither the database nor Qt, so layout code can build it headlessly. Millimetres, origin on the bundle axis, +y down. `ConductorSpec` (conductor dia, OD, metal colour, insulation colour, optional stripe colour + angle), `ShieldSpec`, `JacketSpec`, `CableSpec` (one wire, moved as ONE unit: its conductors, optional shield, optional jacket; `CableSpec.fit_to_od(...)` sizes `count` identical conductors to fill an overall OD), `PlacedCable` (a cable at x/y with the lay length of its layer), `SectionSpec` (the placed cables, bundle outline, layer guide rings, and `run_length_mm`) and `WireDetail` (what the information pane shows). Helpers: `conductor_rgb(material)` (copper unless the name says a plating: tin, silver, nickel, gold, aluminium), `stripe_angle_for(key, index)` (a "random" stripe place that is stable per wire, seeded by the key, so it does not jump on repaint) and `helix_length_mm(run, helix_radius, lay_length)` -- the SAME helix formula the wire service loop uses (`sqrt((2 pi R turns)^2 + height^2)`, turns = run / lay length; a lay of 0 means untwisted, so just the run).

#### section_view.py

`CrossSectionView(QWidget)` -- the custom-drawn left pane. Draws the bundle outline, the layer guide rings and every placed cable (`wire_painter`); click selects a cable (`cable_selected`), dragging moves the WHOLE cable and all its conductors together (`cable_moved`, then `cable_move_finished` -- the place to save). It scales to fit the content as of the last `set_section`/`refit`, and does NOT rescale while a cable is dragged. `render_image(px_per_mm)` draws the section at a fixed scale into a transparent `QImage` independent of the widget's size.

#### section_widget.py

`ConcentricSectionWidget(QWidget)` -- the whole widget: `CrossSectionView` on the left and `WireInfoPanel` on the right in a horizontal `QSplitter` (the same splitter the circuit editor uses; opens 3 : 2). Dragging the sash all the way right closes the information pane and back opens it (`set_info_open()` / `is_info_open()` do the same from code). It follows the selection and a drag (the helix length changes as a cable's distance from the axis does). Built to be drawn into a buffer and shown as a GL texture on the peg board like the floating wire tables: `host_offscreen()` (`WA_DontShowOnScreen` + translucent background + `show()`, which MEMORY.md says a grabbed widget needs), `resize_mm(w, h)` (`PIXELS_PER_MM` = 6.0, the same as `ui.pegboard_table.mdi_host`) and `grab_rgba()` -> `(bytes, width, height)` RGBA8888, the same contract as `PegboardTableHost.grab_rgba`. The pegboard GL object that uploads that buffer through `TextureProgram` and forwards mouse events into it is `objects/objects_pegboard/section.py`, through `section_host.py`. NOT yet built: the code that builds a `SectionSpec` / `WireDetail` from the database and the circuit solver (`CircuitSolution.amps` / `.temperature`). Placement + size of the widget live in the `pjt_pegboard_sections` table (`database/project_db/pjt_pegboard_section.py`).

#### wire_painter.py

QPainter drawing of one cable, in millimetres (the caller has translated to the cable's centre and scaled). `paint_conductor` = the insulation disc (the OD, primary colour), the stripe's cross-section (a piece of the insulation ring, `STRIPE_ARC_DEG` wide and `STRIPE_DEPTH_FRACTION` of the wall deep) and the metal conductor disc. `paint_cable` = jacket disc, shield ring (with a dotted line so it reads as a braid), the core fill, then every conductor at its place in the pack; a coax is the same drawing (one conductor whose "insulation" is the dielectric, plus shield and jacket). Outlines are 1 px cosmetic pens, so they stay 1 px at any zoom.
