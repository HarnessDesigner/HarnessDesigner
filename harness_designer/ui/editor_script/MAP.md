## FILES

#### __init__.py

Package init for the Script Editor dock; no content beyond the standard package marker.

#### assistant_panel.py

Defines `AssistantPanel(QtWidgets.QWidget)` — the Claude assistant UI under the editor: checkboxes for what context to send, a preview, Send/Stop, the streamed answer, and Insert/Replace/Copy/View-changes actions on returned code blocks. All actual API work goes through `harness_designer/plugins/plugins/claude_ai/` (`ClaudeJob`/`Conversation`/`ClaudeClient`, formerly `harness_designer/claude/` — relocated as part of wrapping it as a plugin, see `plugins/plugins/claude_ai/MAP.md` — and MEMORY.md's "Claude API" entry, which still names the old path) — this panel never talks to `anthropic` directly, and nothing in this directory should import `anthropic` or handle the key itself; authentication uses the user's own keyring-stored key. The prompts/tool definitions it assembles come from `scraping/assistant.py`/`assistant_tools.py` (`AssistantContext`, `AssembledMessage`, `CodeBlock`). Key methods: `send()` (assembles the message, starts a `ClaudeJob`, wires its callbacks to `_text_arrived`/`_finished`/`_failed`/`_cancelled`/`_tool_called`), `_show_diff()`/`_toggle_diff()` (view-changes), `_insert`/`_replace`/`_copy` (apply a chosen `CodeBlock` back into the editor), `new_chat()`, `stop()`, `shutdown()`.

#### console_panel.py

Defines `ConsolePanel(QtWidgets.QWidget)` — the Console tab: lists runs started by Run (F5), shows the selected run's output, and Stop (`Shift+F5`). Runs are `scraping/runner.py`'s `ScriptRun`s, executed in threads of this same process — scripts run in a **thread** of the app process, not a child process, an explicit user decision (2026-10-17) taken against the agent's own recommendation; Stop raises `SystemExit` in the thread, which cannot reach a thread blocked in `time.sleep`, a blocking socket read, `.join()`, or a bare `except`, and a catastrophic regex can freeze the whole app — this is accepted, mitigated only by a warning popup and teaching examples (see `SCRAPER_DESIGN.md` "Running scripts"); do not move this to a child process without asking first. `stop_selected()` emits a `stopIgnored` signal via `_check_stops` if a run is still going ~2s after Stop was requested, which the owning `ScriptEditorPanel` turns into a warning dialog (`_stop_ignored`/`_show_stop_warning`). `_tick`/`_sync`/`_collect` poll and append live output from running scripts.

#### message_dialog.py

Defines `ask(parent, title, text, buttons, extra)` / `MessageDialog(dialog_base.BaseDialog)` / `Answer` — a message box with standard buttons plus one optional extra button, used for "save changes?", general problems, and the "script did not stop" warning.

#### script_editor.py

The two top-level classes for the scraper tool's Script Editor dock: a code editor for writing/running scraper scripts, with a Claude assistant panel and a run console as tabs underneath. Design lives in `SCRAPER_DESIGN.md` (repo root, "Phase 3 as built") — read it in full before making any non-trivial change here, per MEMORY.md's standing instruction for anything under `scraping/`, `ui/web_viewer/`, `ui/editor_script/`, or `ui/scraper_inspector/`. `MainFrame.show_script_editor()` creates this dock lazily on first use (no menu entry yet — only the General toolbar's Script Editor button, icon `note_pen`), and `MainFrame._link_scraper_docks()` joins it to the Web Browser dock afterward. `ScriptEditorPanel(QtWidgets.QWidget, insertion.SnippetSink)` is the actual editor widget — wraps a `CodeEditorCtrl` (from `ui/widgets/`), a toolbar (New / Open / Save, Run / Stop, Examples), and two tabs (Assistant, Console); being a `SnippetSink` means the scraper inspector's captured code snippets land directly in it (`insert_snippet`). Key responsibilities: `run_script`/`stop_script` (delegates to `scraping/runner.py`, see `console_panel.py`), `new_script`/`open_script`/`save_script`/`save_script_as` with unsaved-changes prompting (`_can_discard`, `_ask_save_changes`, using `message_dialog.ask`), and an autosaved working copy (`_autosave`/`_restore_scratch`/`_remove_scratch`) so an unsaved script survives a crash/restart independent of explicit Save. `ScriptEditor(DockBase, insertion.SnippetSink)` is the dock wrapper — creates the `plugins.plugins.claude_ai.client.ClaudeClient` used by the Assistant tab (import path updated by the `claude/` → `plugins/plugins/claude_ai/` relocation — double check this call site still resolves), forwards `taken_names`/`insert_snippet` to the panel, and `_open_settings()` opens the API-key dialog from the assistant's settings button. Module-level helpers: `_toolbar_icon(picture)`, `stop_warning_text(run)`. Generated/Claude-written scripts may use `requests` + `beautifulsoup4` + `lxml`; there are no unit tests for this area (per MEMORY.md's standing "Do not write unit tests" note), and importing `harness_designer` has `Config`/logger side effects, so a scratch experiment touching this code must load modules without running the package `__init__`.
