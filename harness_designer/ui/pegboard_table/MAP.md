#### column_defs.py

Append-only `COLUMN_DEFS` catalog (no imports -- a pure data module) plus the default-visible-column sets for each table context. `COLUMN_DEFS[33]`, `'Branch'`, is `transition_only`: it lists the `branch_id`s of a transition's own branches that a wire is routed through, sourced from `pjt_wire_paths`. Transition tables default to `DEFAULT_VISIBLE_COLUMNS_TRANSITION`; a table whose column choice was already saved keeps it (the Branch column can be added back via the header's right-click column picker). As of 2026-09-29, the code that writes the `bundle_id`/`transition_branch_id` tags onto `pjt_wire_paths` does not exist yet, so the Branch column (and the transition table's rows generally, and the wire-highlight's bundle/branch part) is empty until that write path is built -- don't "fix" this by falling back to the old concentric-tables design; there is no fallback path, by design.

#### mdi_host.py

`PegboardTableHost(QtWidgets.QMdiArea)` and `_CursorAndCloseFilter(QtCore.QObject)` -- hosts a `wire_table.WireTable` inside an off-screen `QMdiSubWindow` purely so its rendered appearance can be grabbed as a texture (the same `WA_DontShowOnScreen` + `.grab()`-to-GL-texture technique explored for the Peg Board Editor's floating spreadsheet-style overlay tables; see `harness_designer/ui/editor_pegboard/MAP.md` DESIGN NOTES's Peg Board Editor entries for the fuller story of why a real Qt widget grabbed to a texture was chosen over a from-scratch GL-drawn table). `_CursorAndCloseFilter.eventFilter` intercepts cursor/close-button events on the hosted sub-window so they still behave sensibly despite the host never actually being shown on a real screen. (2026-11-01) `grab_rgba(factor=1)` can capture at a whole-number multiple of the pixels for printing: `grab_scaled(widget, rect, factor)` paints the (not re-laid-out) widget onto a QImage whose devicePixelRatio is `factor`, so text and lines are re-rasterised sharp rather than enlarged (bitmap icons stay as soft as they were). `print_factor(size, wanted)` lowers a wanted multiple to fit `_PRINT_MAX_SIDE` (8192 px) and `_PRINT_MAX_PIXELS` (36 Mpx).

#### wire_table.py

`WireTable(_base.EditorList)` -- the peg-board wire table widget: columns driven by `column_defs.COLUMN_DEFS`, cross-table wire-selection sync (`wire_selected`/`wire_deselected` signals, part of the "selecting a wire row in any wire table lights everything it touches blue" highlight feature -- see `objects_pegboard/wire_highlight.py` and MEMORY.md's Peg Board entries), and the transition-only Branch column described under `column_defs.py` above. `WireTable.mirror_selection(db, wire_id)` (classmethod) selects the wire in every live table of the project that lists it, and clears the ones that don't (or all, for `None`), with the tables' own signals suppressed -- used when the pick came from a cable in a concentric section widget. One table exists per transition (none per branch) -- `PJTTransition.wires` is de-duplicated so a wire entering one branch and leaving another, which appears on two branches' lists, is still exactly one row in the single table.

**Rows are wires, cables and conductors (2026-11-11, user's spec):** a housing's table has a row per plain wire and per CONDUCTOR of a cable that plugs into it: ONE row however many pieces of wire its lead is cut into (a wire service loop cuts a lead in two), with the conductor's own colour, stripe, core, size and the picture of that one conductor (`_CONDUCTOR_SQL`, the cable's part number / manufacturer stay). A bundle's or transition's table has a row per plain wire and per CABLE (its part's values and picture) and a double click (`_on_activated`) expands it into the cable's conductors (and folds them away again). Every row of a cable (the cable's and each conductor's) has the cable's colour (`_CableBackgroundDelegate`; the colour is the cable's own, stored in `pjt_cables.bg_color` so it is the same in every table and after a restart, and DARK for the dark theme, so the delegate draws light text on it; the cable's own row is `lighter(145)`; `_cable_brush`, cached in `_cable_brushes`, dropped on `_rebuild`). The rows are worked out in Python (`_build_row_specs`: `(key, kind, wire, cable, conductor, group, depth)`, kind `_KIND_WIRE` / `_KIND_CABLE` / `_KIND_CONDUCTOR`) and written into the query as a VALUES table (`_scope_sql`), so the query is rebuilt whenever they change (`_rebuild`; `refresh_wire_scope`); the key of a row is the wire's, the cable's or the conductor's id (the id column of a row, `GetSelection`). Sorting (header clicks) orders the groups by the sort of their first row and keeps a cable's conductors under it (`wt_heads` in the query). `record_count` is the number of rows (it was the count of every `pjt_wires` row). **Linked selection:** a selected row is selected in every other table that has it: `_resolve_key` maps a wire id to its conductor's row, and a conductor inside a cable that is folded in that table EXPANDS the cable there and selects the row; `wire_ids_for_key` gives the wires a row stands for (every piece of a conductor's leads, all those of a cable's conductors) -- what `WireHighlight.show` lights (it now takes a list). A conductor or cable row is not dragged as a wire (`selected_wire_id`). Checked with the real table on stand-ins for the database layer, its SQL run on a copy of the user's database (`twist/wire_table_rows_test.py`), not in the app: the images of conductor and cable rows (`_get_icon`, through `build_wire_icon`) and the painting of the colours were not run.

**Deselect reaches every table (2026-11-11, user's bug report):** a selection is mirrored into the other live tables of the project (`_on_row_selected` -> `_select_wire`), but clearing it only cleared the table the user clicked in, so the others kept the row selected and a cable's rows there showed the selection colour instead of the cable's. `_on_row_unselected` now clears every other live table (`_clear_wire`, which asks the host to regrab its texture), and `_on_row_selected` clears the tables that do not list the newly picked wire instead of leaving their old selection. Checked on stand-ins (`twist/wire_table_rows_test.py`), not in the app.
