## FILES

#### __init__.py

Package init for the circuit table editor dock; no content beyond the standard package marker. Note: this directory was named `editor_ciruit` (a typo) until 2026-10-24, when it was renamed to `editor_circuit` at the user's request; older notes, audits and commits may still use the old name.

#### bitmaps.py

Pixmap helpers for the circuit table's connector columns: `scale_housing_image`/`scale_housing_pixmap`, `placeholder_connector_image`/`placeholder_connector_pixmap`, and `painting(device)`. The connector pictures the table builds on its worker thread are drawn as `QImage`, because a `QPixmap` may only be made on the GUI thread (the `*_pixmap` versions are GUI-thread wrappers). Every painter runs inside the `painting(device)` context manager (it always ends the painter: a `QPainter` left active when a draw call raises makes Qt abort the process). The WIRE pictures are no longer made here: since 2026-10-25 they come from `harness_designer.image.images.build_wire` (see `editor_widget.py`), and the old swatch painter (`make_wire_pixmap`, `cached_wire_pixmap`, `conductor_color`, `_valid_color`, `WIRE_PIXMAP_CACHE`) was removed.

#### design_rules.py

The DRT (design-rule-check) logic — `Severity` enum, `DRTIssue`/`SplitSuggestion` dataclasses, AWG/mm² conversion helpers (`awg_to_mm2`, `awg_to_od_mm`, `resolve_awg`), `run_drt(row)` (the actual rule evaluation), and `generate_suggestions(row, project_db)` (bundle-split suggestions, using `bundle_wire_ods`/`find_bundle_by_name`). Reviewed 2026-10-24. `run_drt` checks each wire's current (`CircuitRow.wire_loads`, from the solver) against that wire's own gauge when it has them, else the first wire's gauge as before; it also reports `V_DROP_ALLOWED` (the drop to a load is over what the user allows there) and `OVER_TEMP` (a part the solver finds over its rating). `bundle_wire_ods` is no longer a stub and `generate_suggestions` finds bundles by id.

#### editor_circuit.py

Defines `EditorCircuit(DockBase)` — the dock wrapper, and its own `EditorCircuitPanel(editor_widget.EditorCircuitPanel)` — a thin subclass of the "real" panel class defined in `editor_widget.py`, adding only a mainframe-aware `__init__` and a no-op-safe `Refresh()`. `EditorCircuitPanel` is defined twice in this directory — once here (the thin `DockBase`-adjacent wrapper subclassing the other one) and once in `editor_widget.py` (the real `QtWidgets.QWidget` implementation); when looking for "the" `EditorCircuitPanel`, check which module imported it — the real logic is in `editor_widget.py`'s version. `EditorCircuit` is a `DockBase`: the one dock (title "Circuit Editor", object name `editor_circuit`) comes from there, and `editor` is the plain panel inside it. Anything that needs the dock (the View menu, tabbing it with the object editor) uses `.dock`; anything that needs the table uses `.editor`.

#### editor_widget.py

The real implementation (~1800 lines, the bulk of this directory) of the circuit table editor dock: a spreadsheet-style view of every circuit in the project (one row per circuit/wire), with per-row design-rule-check (DRT) severity, wire/connector thumbnails, and split suggestions for oversized bundles. `CircuitRow` is one built row's display data (wire/connector pixmaps, DRT issues, bundle membership, etc.), built by `_build_row()`/`_build_worker` off the UI thread (`_BuildWorker(QtCore.QObject)` plus a QThread) so loading a large project's circuit table doesn't block the GUI — row building is explicitly threaded to avoid blocking the GUI on large projects, so don't move DB/row-construction work back onto the UI thread without re-checking why this split exists. `CircuitTableModel(QtCore.QAbstractTableModel)` is the Qt model backing the table, including drag-and-drop support (`mimeTypes`/`mimeData`/`dropMimeData`). `CircuitFilterProxy(QtCore.QSortFilterProxyModel)` does text + severity filtering over the model. `WireDelegate`, `ConnectorImageDelegate`, `NumericDelegate` (`QtWidgets.QStyledItemDelegate` subclasses) handle custom cell painting for the stacked wire pictures, connector thumbnails, and numeric formatting. `CircuitDetailPanel` is the selected row's detail view (connector strip image, full text fields). `CircuitTableView(QtWidgets.QTableView)` is the table widget itself, wired to `mainframe`. `EditorCircuitPanel(QtWidgets.QDockWidget)` is the actual top-level panel — builds the toolbar (severity filter, etc.), owns the model/proxy/view/detail-panel, and exposes `load_project()`/`refresh()`/`highlight_circuit(circuit_db_id)` — this is the real `EditorCircuitPanel` (see `editor_circuit.py`'s note above). **Until 2026-10-24 nothing ever called `load_project`, so the dock opened empty and none of this had run.** `Project.__init__` now calls `load_project(ptables)` (and `MainFrame.unload` calls `load_project(None)`); the rows are only built while the dock is on screen (`load_project` builds right away if it is visible, otherwise `showEvent` does), so an unopened dock costs nothing and an opened one is current with the circuits made, merged or deleted since. The row build runs on a worker thread and has never been exercised end to end: `bitmaps.py` makes `QPixmap`s there, which Qt only supports on the GUI thread, so watch for that the first time the dock is opened with real circuits. Clicking a row selects that circuit (after deselecting the current selection), which highlights all of its members through `Circuit.set_selected`; the old per-wire `identify([0.2, 0.6, 1.0, 1.0])` passed a list where a `GLMaterial` is required and is gone. `_bundles_for_circuit` now lists the bundles a circuit's wires are routed through, from the `bundle_id` tags on `pjt_wire_paths` (`PJTWirePathsTable.bundle_ids_for_wire`). `_build_row` runs on the `_BuildWorker` thread, so it only makes `QImage`s; `EditorCircuitPanel._on_loaded` turns them into `QPixmap`s on the GUI thread before the model gets the rows (2026-10-24). Checked with real Qt on the offscreen platform, which does not print Qt's own off-thread-pixmap warning, so the old behaviour was not reproduced; the change follows Qt's documented rule. Reviewed 2026-10-24. `_build_row` takes the load, the drop to each load, the current in each wire and the hot parts from `circuit.solve()` (a terminal's `voltage_drop` is the drop the user ALLOWS, not a measurement). The worker never loses a circuit silently (an unreadable one gets an error row and a log line) and always emits `finished`; `refresh` remembers a request made during a build and `_on_loaded` ignores a stale project's result; numeric columns sort as numbers (`CircuitFilterProxy.lessThan`); drag and drop moves the right rows and survives any id; the error count counts only errors. Still true: dragging rows only reorders the view, and "Resistance" is the plain sum of the wires' resistances. `EditorCircuitPanel` is a plain `QWidget`, like every other editor's panel. **Crash fixed 2026-10-24:** selecting a circuit ended the app with `AttributeError: 'Material' object has no attribute 'lower'` (`_build_row` stored the wire's INSULATION `Wire.material` as the conductor; the conductor is `Wire.core_material`, a `Plating`, whose swatch colour is `.color`). `_build_row` now reads the wire/stripe colours from the catalog `Color` (`.name`, `.rgb`; the nil id means "not set") and the conductor from `core_material`. `cell_edited` is `Signal(object, int, object)` (the id is bytes; as `int` the edit never arrived). Every Qt-facing method is wrapped by `_guarded`, which logs once per (method, error) and returns a fallback, because this PySide6 build aborts the process when an exception escapes a slot or override (see `run.py`). **Wires, To Pin and Delete Circuit (user, 2026-10-25).** A circuit does not use one wire throughout: where it branches off a splice or another terminal the wire can change. `_build_row` now builds `CircuitRow.wires`, one `WireInfo` per distinct wire PART (`_wire_infos`; wire service loops count as wires, and the members of one part are one entry with their counts, total length/resistance/weight, the most current any of them carries and whether any is bundled), each with what is specific to the part (part number, gauge, insulation, colours, conductor, OD, conductors, shielded). The old first-wire fields stay on the row because the design rules read them. Each entry's picture comes from `harness_designer.image.images.build_wire` (`_wire_part_images`; only single-conductor, unshielded parts with their colours set, otherwise `images.no_image`: the rule the parts editor, the peg-board wire table and the BOM already follow), made as a `QImage` on the worker thread at `WIRE_TABLE_SIZE` (100x25) and `WIRE_PANEL_SIZE` (200x50) and cached by colour names in `_WIRE_IMAGES` (reset by `refresh()`); `_on_loaded` and `show_row` turn them into `QPixmap`s. The Wire column (`WireDelegate`) stacks one 100x25 picture per distinct wire and its `sizeHint` makes the cell taller, so the vertical header is `ResizeToContents` (fixed row heights would not follow a sort). The Gauge column lists every distinct gauge. A To Pin column follows To (`COL_TO_PIN`; the From pin column is headed From Pin) and is searched by the filter. The detail panel has a Wires tab (second; DRT Issues is third, Suggestions fourth): one card per distinct wire with its 200x50 picture centred ABOVE its data (`_wire_text`); the Totals tab no longer carries one wire's gauge/conductor/OD/ampacity. Right-clicking a row offers Delete Circuit (`CircuitTableView.contextMenuEvent` -> `delete_requested` -> `EditorCircuitPanel._on_delete_requested`): a Yes/No, default No, that says it cannot be undone and how many objects leave the circuit, then `Circuit.delete()`, which sets the circuit of every wire, wire service loop, splice and terminal in it to NULL (the objects are kept) and reloads the table. **Selection stays in step with the circuit (user, 2026-10-25):** `CircuitTableView.selected_row()` is the one place that maps the selected proxy row to its `CircuitRow`. `EditorCircuitPanel.deselect_circuit(db_id)` clears the table's selection only when the selected row is that circuit's (so a click on another object, or empty space, in an editor, which ends in `Circuit.set_selected(False)` -> the views -> `deselect_in_editor`, un-selects the row too; for any other row it exits). `_on_row_selected` remembers the circuit its row selected (`_selected_circuit_db_id`) and, when the row is unselected (empty table space, row toggled off, a filter hiding it), calls `set_selected(False)` on that circuit if it is still selected. The circuit marks itself deselected before its views call the editor, which is what stops the two calling each other. A table rebuild (`_model.load`) drops the row without a signal, so it does not deselect the circuit. Wire service loops count as wire in the row's totals (length, resistance, weight) and in the per-wire overcurrent rule (user, 2026-10-25; `_add_wire_totals`): a loop knows nothing of bundles, so it is checked against the bundled ampacity when any wire of its circuit is bundled. `CircuitRow.wire_db_ids` stays the wires' ids only (it is used to look wires up). It used to derive from `QDockWidget`, so the dock `DockBase` builds around it held a SECOND dock with its own title bar, float and close buttons (a window inside a window; it was the only panel in the UI that was a `QDockWidget`). Fixed 2026-10-24.
