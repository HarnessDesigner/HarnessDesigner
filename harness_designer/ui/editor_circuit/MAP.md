## FILES

#### __init__.py

Package init for the circuit table editor dock; no content beyond the standard package marker. Note: this directory was named `editor_ciruit` (a typo) until 2026-10-24, when it was renamed to `editor_circuit` at the user's request; older notes, audits and commits may still use the old name.

#### bitmaps.py

Pixmap helpers for the circuit table's connector columns: `scale_housing_image`/`scale_housing_pixmap`, `placeholder_connector_image`/`placeholder_connector_pixmap`, and `painting(device)`. The connector pictures the table builds on its worker thread are drawn as `QImage`, because a `QPixmap` may only be made on the GUI thread (the `*_pixmap` versions are GUI-thread wrappers). Every painter runs inside the `painting(device)` context manager (it always ends the painter: a `QPainter` left active when a draw call raises makes Qt abort the process). The WIRE pictures are no longer made here: since 2026-10-25 they come from `harness_designer.image.images.build_wire` (see `editor_widget.py`), and the old swatch painter (`make_wire_pixmap`, `cached_wire_pixmap`, `conductor_color`, `_valid_color`, `WIRE_PIXMAP_CACHE`) was removed.

#### design_rules.py

The DRT (design-rule-check) logic — `Severity` enum, `DRTIssue`/`SplitSuggestion` dataclasses, AWG/mm² conversion helpers (`awg_to_mm2`, `awg_to_od_mm`, `resolve_awg`), `run_drt(row)` (the actual rule evaluation), and `generate_suggestions(row, project_db)` (bundle-split suggestions, using `bundle_wire_ods`/`find_bundle_by_name`). Reviewed 2026-10-24. `run_drt` checks each wire's current (`CircuitRow.wire_loads`, from the solver) against that wire's own gauge when it has them, else the first wire's gauge as before; it also reports `V_DROP_ALLOWED` (the drop to a load is over what the user allows there) and `OVER_TEMP` (a part the solver finds over its rating). `bundle_wire_ods` is no longer a stub and `generate_suggestions` finds bundles by id.

#### editor_circuit.py

Defines `EditorCircuit(DockBase)` — the dock wrapper, and its own `EditorCircuitPanel(editor_widget.EditorCircuitPanel)` — a thin subclass of the "real" panel class defined in `editor_widget.py`, adding only a mainframe-aware `__init__` and a no-op-safe `Refresh()`. `EditorCircuitPanel` is defined twice in this directory — once here (the thin `DockBase`-adjacent wrapper subclassing the other one) and once in `editor_widget.py` (the real `QtWidgets.QWidget` implementation); when looking for "the" `EditorCircuitPanel`, check which module imported it — the real logic is in `editor_widget.py`'s version. `EditorCircuit` is a `DockBase`: the one dock (title "Circuit Editor", object name `editor_circuit`) comes from there, and `editor` is the plain panel inside it. Anything that needs the dock (the View menu, tabbing it with the object editor) uses `.dock`; anything that needs the table uses `.editor`.

#### editor_widget.py

The real implementation (~1800 lines, the bulk of this directory) of the circuit table editor dock: a spreadsheet-style view of every circuit in the project (one row per circuit/wire), with per-row design-rule-check (DRT) severity, wire/connector thumbnails, and split suggestions for oversized bundles. `CircuitRow` is one built row's display data (wire/connector pixmaps, DRT issues, bundle membership, etc.), built by `_build_row()`/`_build_worker` off the UI thread (`_BuildWorker(QtCore.QObject)` plus a QThread) so loading a large project's circuit table doesn't block the GUI — row building is explicitly threaded to avoid blocking the GUI on large projects, so don't move DB/row-construction work back onto the UI thread without re-checking why this split exists. `CircuitTableModel(QtCore.QAbstractTableModel)` is the Qt model backing the table, including drag-and-drop support (`mimeTypes`/`mimeData`/`dropMimeData`). `CircuitFilterProxy(QtCore.QSortFilterProxyModel)` does text + severity filtering over the model. `WireDelegate`, `ConnectorImageDelegate`, `NumericDelegate` (`QtWidgets.QStyledItemDelegate` subclasses) handle custom cell painting for the stacked wire pictures, connector thumbnails, and numeric formatting. `CircuitDetailPanel` is the selected row's detail view (connector strip image, full text fields). `CircuitTableView(QtWidgets.QTableView)` is the table widget itself, wired to `mainframe`. `EditorCircuitPanel(QtWidgets.QDockWidget)` is the actual top-level panel — builds the toolbar (severity filter, etc.), owns the model/proxy/view/detail-panel, and exposes `load_project()`/`refresh()`/`highlight_circuit(circuit_db_id)` — this is the real `EditorCircuitPanel` (see `editor_circuit.py`'s note above). **Until 2026-10-24 nothing ever called `load_project`, so the dock opened empty and none of this had run.** `Project.__init__` now calls `load_project(ptables)` (and `MainFrame.unload` calls `load_project(None)`); the rows are only built while the dock is on screen (`load_project` builds right away if it is visible, otherwise `showEvent` does), so an unopened dock costs nothing and an opened one is current with the circuits made, merged or deleted since. The row build runs on a worker thread and has never been exercised end to end: `bitmaps.py` makes `QPixmap`s there, which Qt only supports on the GUI thread, so watch for that the first time the dock is opened with real circuits. Clicking a row selects that circuit (after deselecting the current selection), which highlights all of its members through `Circuit.set_selected`; the old per-wire `identify([0.2, 0.6, 1.0, 1.0])` passed a list where a `GLMaterial` is required and is gone. `_bundles_for_circuit` now lists the bundles a circuit's wires are routed through, from the `bundle_id` tags on `pjt_wire_paths` (`PJTWirePathsTable.bundle_ids_for_wire`). `_build_row` runs on the `_BuildWorker` thread, so it only makes `QImage`s; `EditorCircuitPanel._on_loaded` turns them into `QPixmap`s on the GUI thread before the model gets the rows (2026-10-24). #### Circuits: data model, membership and chain rules (built 2026-10-24/25; none of it confirmed in the GUI)
A circuit is a numbered, named group (`pjt_circuits`: `circuit_num`, `name`, `notes`, `description`, `return_type`; project-only) that wires, splices, terminals and wire service loops join through their own `circuit_id` column (exactly those four tables; no other table points at a circuit).
- **Code:** `database/project_db/pjt_circuit.py` (`PJTCircuit`, `PJTCircuitsTable`), `handlers/wire_circuit.py` (`reconcile_wire_circuit`), `objects/circuit.py`, `Project.create_circuit()` (the ONE place a circuit is created after load), `add_circuit`/`delete_circuit`/`get_circuit`/`merge_circuits`. Member id lists are cached; every `circuit_id` setter and `insert`/`delete` of the four member classes calls `PJTCircuitsTable.members_changed(*ids)`. Project tables are `TableData`-cached, so `select()` is an in-memory scan (it now has a lazy per-column index, see `project_db/MAP.md`). `select('db_id', ...)` is not a column on any pjt table; use `'id'`.
- **Auto-create / merge:** `reconcile_wire_circuit(project, wire)` runs after a wire's ends attach (three add-wire handlers, `wire_snap.commit_snap`, `wire_drag_base.merge_wire_into`): no circuit anywhere and an end is a terminal -> create one (first terminal, start end first, becomes the start terminal); one circuit -> everything circuit-less joins it; two or more anywhere in the whole chain -> Yes/No dialog, then merge into the START side's circuit (No changes nothing). Deleting a circuit detaches its members (`circuit_id = None` in one gesture), never deletes them.
- **Chain rule (user):** a circuit added to, or changed for, any member reaches the entire chain of connected objects (`PJTCircuitsTable.connected_members` via `_walk_circuit`, `propagate`, `PJTCircuit.adopt`). The four `circuit_id` setters propagate when set to a circuit (never when set to None). `add_member`/`merge_from` pause propagation (`propagation_paused`), place their members, and propagate once. Taking over members of ANOTHER circuit asks first (`PJTCircuitControl._confirm_move`, asked BEFORE a circuit is created for a new name/number so No leaves no empty circuit). Start terminal: a joining terminal is demoted; promoted only when the circuit has no start and the terminal has no load. Not built: deleting a wire/terminal/splice never empties or re-splits a circuit; unplugging does not touch circuits; the number/name fields cannot unassign a host.
- **Selection / views:** every selectable `ObjectBase` needs a view (a placeholder is fine) in all three canvases, because the canvas holds the selected object and `MouseHandlerBase.on_left_up` deselects through it; a view-less selection raised in `paintGL` and, in this PySide6 build, ended the process. `Circuit` has inert placeholder views (`objects_3d|objects_schematic|objects_pegboard/circuit.py`, built like an unplaced `Note`, `obb` None so it is unpickable). Members light up through `materials.Circuit` (amber emissive, colour is a class constant, not in `Config.colors`) via `identify()`, not by being selected. `CanvasBase._draw_scene` skips and logs (once) a view-less selection. Deselecting in an editor calls `Circuit.deselect_in_editor()` -> `EditorCircuitPanel.deselect_circuit(db_id)`, which clears the table row only if it is that circuit's (that check ends the loop). Open: a table rebuild drops the row with no signal.
- **Open:** the four `objects_schematic` context menus are empty stubs (tracing from the schematic does nothing); a circuit has no properties control; `LINKED` return type is not built (a shared ground wire carries the sum of every circuit returning through it, so the drop must be solved across circuits).

#### Circuit electrical model: load, temperature, derating, bundling (built 2026-10-24; unverified in the GUI, assumptions flagged)
- **Terminal rules (user):** a terminal has a load OR a voltage, never both; only one terminal per circuit has a voltage (that is `is_start`). Whole-circuit load walks every wire, branch, splice and terminal; load of a wire/splice counts only terminals outward from it, at the voltage reduced by the drop up to that point. `circuit_map` must handle terminals with several wires and nested branching splices.
- **Solver (`database/project_db/circuit_solver.py`, `solve_circuit`/`CircuitSolution`; `PJTCircuit.solve()`, `total_circuit_load`, `load_at`, `voltage_at`):** ideal source, series resistances, loads in parallel with what continues past a terminal; supply side only. A terminal's Load is its rated current at the circuit voltage, modelled per `LoadType` (resistive `V/load` is the default, constant power, constant current; my choice, the user never picked). `return_type`: `CHASSIS` (return not modelled) or `MIRRORED` (every series resistance counts twice). Parallel wires between the same two junctions share the current by conductance (`_parallel_wires`). `PJTCircuit.voltage_drop` is the largest ALLOWED drop, not a measured one. `PJTWire.resistance` uses the routed `length_mm`.
- **Temperature:** resistance at the part's own temperature (copper 0.00393 per deg C, wire/loop resistance taken at 20 C), rise = theta * I^2 * R(T) solved with an outer loop until it settles, runaway detected, over-temperature flag computed on the fly (nothing stored), unrated ("Unknown") never flagged. Project-side columns `operating_temp` (FLOAT NULL) on `pjt_wires`, `pjt_wire_service_loops`, `pjt_splices`, `pjt_terminals` and `load_type` on `pjt_terminals`. Replication on connect (`wire_circuit._replicate_operating_temp`): an unset part takes its neighbours' value; differing values ask Yes/No; split/merge/splice/loop creation copy it. Each project row has `part_data()` (mixin `project_db/mixins/operating_temp.py`) collecting resistance, thermal resistance, ambient (default 20 C, `DEFAULT_AMBIENT_C`), rated maximum (parsed from the part's `max_temp` name); it is the one place derating data is consulted. UNCALIBRATED assumptions: wire heat transfer 10 W/m^2K, terminal/splice thermal resistance 40 K/W, `BUNDLE_HEAT_TRANSFER = 10`, `BUNDLE_PACKING_FACTOR = 1.0`; the return side is not heated; the voltage terminal's contact resistance heats but does not drop voltage.
- **Derating (global DB, manufacturer data, static per part):** table `deratings` (`create_database/deratings.py`, `global_db/derating.py`, `GLBTables.deratings_table`): nullable `terminal_id`/`wire_id`/`splice_id` (exactly ONE set, enforced in `DeratingsTable.insert`, which also needs `max_amps` or `derating_factor`), `idx`, `ambient_temp_c`, `conductor_count` (a bundling row), `max_amps`, `derating_factor`. The columns are my proposal, unconfirmed, and nothing populates the table. Caching is the user's design: the part TABLES call `part.load_deratings()` from their own `__getitem__` (an `__init__` hook on the part was rejected); `part.deratings` is a tuple served from memory; `insert` drops the cache entry. The sibling `harness_designer_database` repo has the same table (`builder/create_database/deratings.py`, `TABLE_MODULES`; uncommitted there as of 2026-10-24). The solver calibrates theta from the table (`circuit_solver.calibrate_theta`: a part at its limit is at its rated maximum); rows with `conductor_count` are bundling rows. The table branch: if a table exists use it, otherwise calculate.
- **Bundle ambient:** a wire's ambient rises by the OTHER wires' heat per metre over the bundle surface (`pi*D*BUNDLE_HEAT_TRANSFER`), warmest bundle wins. The bundling type is DERIVED: a concentric row with layers -> CONCENTRIC, bundled without one -> UNORGANIZED, in no bundle -> unchanged. Circuits sharing a bundle are solved together (`solve_bundled`, fixed point). Bundle membership relies on route-row `bundle_id` tags. Not built: a project default ambient setting; a ring through 3+ junctions is still cut. Found, not fixed: `SplicesTable.__getitem__` by string looks in a `name` column that does not exist.
- **Performance:** the solver math is cheap (about 2 us/member cold, 25 us with temperature feedback; compiling untyped code gains only ~1.5x, so no Cython rewrite). The cost was data collection (`TableData.select` scanning every row), fixed by the per-column index and computing a wire's length once per `part_data()`. To compile a scratch module with the build's toolchain call `builder.msvc_env.activate()` then `builder.compiler.compile_one`; do not pip-install pyMSVC.

#### Circuit editor dock and autocomplete rules (user, 2026-10-24/25)
- **Qt rule for this build:** an exception that escapes a slot, paint or model override ends the whole process (no traceback, a faulthandler dump). The dock's Qt-facing methods are wrapped by `editor_widget._guarded` (log once, return a fallback; the user can drop the guards to get the dump). Every `QPainter` in `bitmaps.py` runs inside the `painting()` context manager (a painter left active aborts Qt); other `QPainter` uses in the repo are unaudited. The dock's row build runs on a worker thread, so it draws `QImage`, never `QPixmap`. `EditorCircuitPanel` is a plain `QWidget` (deriving from `QDockWidget` produced two title bars). `Project.__init__` loads the dock and `MainFrame.unload` clears it. Signals carrying bytes ids must be `Signal(object, ...)`. A widget in a hidden tab is not laid out, and a widget must be `show()`n before a test types into it. Showing the dock with a fake `_project_db` starts a refresh that empties the table.
- **Wire data:** `Wire.material` is the INSULATION `Material` row; the conductor is `Wire.core_material` (a `Plating`: `.description`/`.symbol`/`.color`; colours via `Color.name`/`Color.rgb`; a nil id means "not set"). The table shows one picture per distinct wire PART (wires and wire service loops both count), stacked in the cell, from `image.images.build_wire(primary, stripe, conductor)` (400x100, shown at 100x25 in the table and 200x50 in the panel; only single-conductor unshielded parts with colours, else `images.no_image`). `WireInfo` groups per part; the Wires tab has a card per wire; loops are counted in totals (length, resistance, weight) and the per-wire overcurrent rule (a loop counts as bundled when any wire of the circuit is). The dock's design rules still use a fixed NEC/ISO ampacity table, not the part's derating table; dragging rows only reorders the view. Delete Circuit (right-click, Yes/No, default No, says it cannot be undone and how many objects leave) calls `Circuit.delete()` then reloads.
- **Autocomplete / Enter rules (user; follow them for any new autocomplete/Enter code):** (1) a single-line control commits on ONE Enter or a list pick, never per keystroke (`ComboBoxProperty` listens to `returnPressed`/`textActivated` and feeds the completer; the per-keystroke commit had created a circuit per letter); (2) a multi-line control commits on THREE Enters in a row, the third is not added, leaving a single trailing newline (`AutoCompleteTextEdit`, `COMMIT_ENTERS = 3`; `AutocompleteStringProperty(multiline=...)`); (3) NEVER strip whitespace in the autocompleter or a handler behind it (`new ` must stay `new `); (4) the control carries a tooltip saying how to save. Unfixed: `AutoCompleteComboBox`, `ComboBoxCtrl`, `BitmapAutoCompleteComboBox` still pass Qt's per-keystroke `currentTextChanged`; `ColorProperty`/`BitmapComboBoxProperty` have the per-keystroke commit; the suggested fix is one Enter-or-pick signal on `AutoCompleteComboBox`. `EnumProperty.SetLabels` builds `len(labels) // 3` rows, so it only works for exactly 3 labels (hence the combo for Return Path).
- **Wire slack handler lifetime:** `Wire.delete` must call `WireSlackHandler.release()` first (a deleted wire facade and its handler keep each other alive until GC, still bound to the wire's points, and `_reconcile` then selects a deleted row); `_reconcile` clears the class-wide `_reconciling_any` in an inner `finally` so one raise cannot disable every wire's reconcile.
- **How the user wants me to work:** use `diagnostics/dep_trace.py` for every "who uses / where is" question, one foreground run per target, after reading `diagnostics/CLAUDE.md`; no grep for those.
