#### objectbrowser.py

`add_splice` (fixed 2026-11-11): `PJTSplice.wires` is THREE lists (start, stop, branch point wires), not one; the browser looped over it as if it were flat and raised `TypeError: cannot create weak reference to 'list'` for every splice, so it flattens them (a wire once). `ObjectBrowser(DockBase)` wraps `ObjectBrowserPanel`, which owns the actual scene-tree `QTreeWidget`. The tree has one top-level item per object category (Boots, Bundles, Cavities, Circuits, Covers, CPA Locks, Housings, Notes, Seals, Splices, Terminals, TPA Locks, Transitions, Wires, Wire Markers), rebuilt fresh by `reset()`. Each placed object gets an `add_<type>()` call (`add_boot`, `add_bundle`, `add_cavity`, ...) that inserts a tree item holding a `weakref` back to the object's DB-row facade rather than a strong reference -- when the object is GC'd, the weakref callback (`__remove_refs`) prunes the now-dead item itself, so nothing else in the app needs to explicitly tell the browser to remove an entry. This weakref self-pruning design is one of the few caches in the codebase that is *not* a place to worry about stale strong references, in contrast to the per-table control-widget singletons documented in `ui/prop_ctrls/MAP.md`, which must be cleared explicitly. A canonical entry (the object's one real listing under its type group) is tagged via `_mark_canonical` so it can be told apart from plain-text cross-reference mentions of the same object nested under an unrelated item (e.g. a wire mentioned under the terminal it's attached to). The tree also supports a small path-search query language: `:`/`.` act as path-level separators only when they have no adjacent whitespace (`_PATH_SEPARATOR_RE`'s lookaround, `(?<=\S)[:.](?=\S)`), which is the whole mechanism letting a literal `.`/`:` inside an object's own name (e.g. "Housing 1.5") survive without being misread as a separator -- any change to the path-query syntax must preserve that no-adjacent-whitespace rule or names containing `.`/`:` will mis-parse. **Circuits** have more behaviour than the other categories: the node is labelled with `PJTCircuit.label` (`#3 Fuel pump`, `#3` while unnamed), its Wires / Wire Service Loops / Terminals / Splices listing is rebuilt whenever the circuit's membership changes (`add_circuit` binds `_on_circuit_members_changed` to the row's `'members'` tag; changes are coalesced into ONE rebuild per event-loop turn through `QTimer.singleShot(0, ...)`, keep the user's expanded groups, and a rebuild skips a circuit whose item has left the tree), and right-clicking a circuit item offers Delete Circuit (`_BrowserTree.contextMenuEvent` -> `show_circuit_menu` -> `_delete_circuit`, with a Yes/No confirm). Nothing else in the tree has a context menu. `TreeItem` now also owns the row callbacks bound for it (`add_callback`, unbound in `delete()`) and can forget a cross-reference item (`discard_treeitem`); rebuilding a circuit relies on both so stale entries do not pile up. Selecting a circuit (click) highlights its members through `Circuit.set_selected`; double-clicking one opens nothing, since a circuit has no properties control of its own. **Cables (2026-11-06, step 7):** a Cables category (`add_cable`, from `MainFrame._add_to_object_browser`). A cable's item has a Conductors group with one item per conductor row (the shield marked), each the conductor's own selectable item (object editor: the wire control) with its circuit and, once an end is split, a Leads group of the lead wires. `refresh_cable` lists them again (`Cable.refresh_browser`: after the placement session makes the conductors, a split, a join, and the project load's reconcile) and keeps what was expanded; `_forget_children` undoes everything a listing registered (weakrefs, a conductor node's link to its item, mention records). A circuit's listing has a Cable Conductors group; those items are only mentions (no cross-reference bookkeeping), found from the row's `get_object()`. Not done: a mention of the conductor under the terminal or splice its lead lands on.
