#### editor_pegboard.py

Defines `EditorPegboard(DockBase)` — the dock wrapper, and `EditorPegboardPanel(gl.canvas_pegboard.CanvasPegboard)` — the GL canvas, for the Peg Board Editor: a top-down "manufacturing formboard" view of the harness (real 3D part meshes reused flat, bundle strands instead of individual wires except bare-terminated ones; see MEMORY.md's "Peg Board Editor" entries for the full multi-phase architecture history). Docstrings explicitly describe this file as a "structural mirror" of `editor_3d.py`/`editor_schematic.py` so `mainframe.py`'s per-editor fan-out can treat it uniformly, same dock-creation shape and same thin forwarding methods. `EditorPegboard` also owns `self.wire_highlight` (`objects.objects_pegboard.wire_highlight.WireHighlight`) — lights up in blue whatever a selected wire row (in any wire table: housing, bundle, or transition) touches on the peg board; the actual wire table UI (`WireTable`) lives in the sibling `ui/pegboard_table/` directory, not here. `EditorPegboardPanel.center_on_object(obj)` mirrors `editor_schematic.EditorSchematicPanel.center_on_object`/`editor_3d.Editor3DPanel.center_on_object` exactly, reading the anchor position off `obj.objpegboard` (the peg-board-specific wrapper) rather than `obj` itself. **Drift correction against CODEBASE_MAP.md**: that doc's `ui/` section claims `EditorPegBoard`'s `add_object`/`remove_object`/`set_selected`/`set_clone_obj` are "no-op stubs" because "Phase 1 has no peg-board selection/object model," with real work happening through a separate `load_project(project)` method — this is now stale. `add_object`/`remove_object`/`set_selected` on both `EditorPegboard` and `EditorPegboardPanel` are real, incremental implementations that forward to the inner `gl.canvas_pegboard.canvas.Canvas`, which registers/unregisters `obj.objpegboard` (skipping any object whose peg-board wrapper is inert, i.e. constructed with `vbo=None`); there is also no `load_project` method defined on this file at all — bulk loading is inherited from the base `CanvasPegboard`/`Canvas` class in `gl/canvas_pegboard/`, not overridden here. Only `set_clone_obj` is still a genuine, documented no-op ("Phase 1 has no clone/paste model for the peg board yet" — `EditorPegboardPanel.set_clone_obj`'s own docstring/body is just `pass`). This dock depends on `objects_pegboard/wire_highlight.py` (outside this directory) and on `gl/canvas_pegboard/` for the actual GL rendering/anchor collection — it is a thin UI wrapper, not where the peg-board rendering logic lives.
